# Эмулятор оболочки ОС (Вариант №18, этап 1)

## Общее описание
Данный проект представляет собой минимальный прототип эмулятора командной оболочки UNIX-подобной ОС, реализованный в виде консольного приложения (CLI).
Этап 1 посвящён созданию REPL (Read-Eval-Print Loop) — цикла чтения-выполнения-вывода, который поддерживает диалог с пользователем.
Большинство команд пока являются заглушками, но уже реализованы базовый парсер, обработка ошибок и команда выхода.

### Особенности этапа 1:

Консольный интерфейс.

Приглашение к вводу формируется на основе реальных данных ОС: username@hostname:путь$.

Парсер корректно обрабатывает аргументы в кавычках (благодаря модулю shlex).

Сообщения об ошибках: неизвестная команда, неверное количество аргументов.

Команды-заглушки ls и cd выводят своё имя и полученные аргументы.

Команда exit завершает работу эмулятора.

Обработка прерываний (Ctrl+C, Ctrl+D).

## Функции и настройки
`get_prompt()`
Формирует строку приглашения вида username@hostname:текущий_путь$.
Использует getpass.getuser(), socket.gethostname() и os.getcwd(). Домашняя директория сокращается до ~.

`cmd_ls(args)`
Заглушка команды ls. Принимает список аргументов, выводит ls: [аргументы].

`cmd_cd(args)`
Заглушка команды cd. Требует ровно один аргумент. При неверном количестве аргументов возбуждает ValueError.
Выводит cd: [аргументы].

`cmd_exit(args)`
Завершает работу эмулятора. Не принимает аргументов. При наличии аргументов возбуждает ValueError.
Выводит Выход. и вызывает sys.exit(0).

`main()`
Основной цикл REPL:

Выводит приветствие.

Запрашивает ввод с помощью input(get_prompt()).

Обрабатывает EOFError и KeyboardInterrupt для корректного выхода.

Разбирает строку с помощью shlex.split() (поддержка кавычек).

Ищет команду в словаре COMMANDS.

При неизвестной команде выводит сообщение об ошибке.

Вызывает обработчик, перехватывая ValueError и другие исключения.

### Словарь COMMANDS
Сопоставляет имена команд (ls, cd, exit) соответствующим функциям.

Команды для сборки и запуска
Требования
Python 3.6 или выше.

Дополнительные зависимости отсутствуют (используется только стандартная библиотека).

### Запуск в Windows через run.bat

В корне проекта находится файл `run.bat`, предназначенный для удобного запуска эмулятора в Windows.

Примеры использования
Интерактивная сессия:

```
text
$ python main.py
Введите команду. Для выхода используйте exit.
user@host:~$ ls
ls: []
user@host:~$ cd /tmp
cd: ['/tmp']
user@host:~$ cd
Ошибка: cd: требуется ровно один аргумент
user@host:~$ ls "file with spaces.txt"
ls: ['file with spaces.txt']
user@host:~$ unknown
Ошибка: неизвестная команда 'unknown'
user@host:~$ exit
Выход.
```


# Эмулятор оболочки ОС (Вариант №18, этап 2)

Этап 2 добавляет конфигурацию эмулятора и запуск стартовых скриптов.

## Параметры командной строки

- `--vfs` — путь к физическому расположению VFS. На этапе 2 путь принимается и выводится; сама VFS реализуется на следующем этапе.
- `--startup` — путь к стартовому скрипту.
- `--debug` сохранён для совместимости, но отладочный вывод параметров этапа 2 теперь выполняется при каждом запуске.

Пример:

```text
python src/main.py --vfs ./data/vfs --startup ./scripts/startup.txt
```

## Стартовый скрипт

Стартовый скрипт выполняет команды последовательно. Пустые строки и комментарии `#` и `//` пропускаются. Перед каждой командой выводятся приглашение и сама команда, поэтому выполнение имитирует интерактивный диалог.

Ошибочная строка сообщает об ошибке и не прекращает выполнение следующих строк.

## Скрипты реальной ОС

В каталоге `scripts/` находятся несколько скриптов реальной ОС. Каждый передаёт оба параметра этапа 2:

- `test_linux.sh` — Linux/macOS;
- `test_linux_alt.sh` — второй Linux/macOS сценарий с альтернативными путями;
- `test_windows.bat` — Windows.

Таким образом, каждый ОС-скрипт проверяет и `--vfs`, и `--startup`.

## Запуск

Windows:

```bat
scripts\test_windows.bat
```

Linux/macOS:

```bash
./scripts/test_linux.sh
./scripts/test_linux_alt.sh
```

Интерактивный режим:

```text
python src/main.py --vfs ./data/vfs
```
